## 0. 一句话定义

**知识洋葱（Onion）是一个本地优先的 AI 知识工具：它会像向导一样带着你问下去，每个知识点都能沿 6 个语义层无限下钻，而你出的每一道题、每一次复习、每一处知识缺口都会被回灌到图谱里，形成闭环。**

三句话说清差异：
1. **不是"再问一次 AI"**——它维护的是一棵**有结构的知识树**，每次展开都遵循固定的六层语义骨架，不会变成聊天记录里的碎片。
2. **不是"普通思维导图工具"**——图谱的骨架是**由 AI 按语义规则生成的**，用户只负责点击和选择；并且**有一条引导串告诉用户第一步往哪走**（借鉴 Rabbithole，见 §3.5）。
3. **不是"又一个 AI 笔记"**——它带**掌握度追踪 + 间隔重复 + 缺口检测 + 溯源**，知识会随时间被主动推回面前，且全部数据留在本机、模型由用户自配。

## 2. 核心机制：双轴洋葱模型

这是整个产品最关键的设计决策，直接决定它能不能落地成可用软件。

传统 AI 展开知识点的失败模式是：**每次生成的子节点结构随机**（这次给你"组成部分"，下次给你"历史背景"，下次给你"应用场景"），导致树长歪、无法导航、无法预期。

洋葱模型用**两个正交轴**锁死这个随机性：

```
                    视角 Facet（7 个，环向扇区）
                    ├─ 速览 原理 实证 应用 争议 关系 追问
        ┌───────────────────────────────────────┐
   L0   │              本质                    │  ← 内核：一个定义
        │                                       │
   L1   │            构成要素                  │
        │                                       │
   L2   │            运作机理                  │
        │                                       │
   L3   │            适用边界                  │
        │                                       │
   L4   │            关联网络                  │
        │                                       │
   L5   │            延伸前沿                  │
        └───────────────────────────────────────┘
              层 Layer（6 个，径向同心环）
```

### 轴一：层 Layer（径向同心环）—— 管"结构"

**每一层的语义目标固定不变**，AI 永远按这张表生成子节点。层数 = 语义深度，不是对话轮数。

| 层 | 名称 | 语义目标 | 典型子节点 | 子节点数 |
|---|---|---|---|---|
| **L0** | 本质 | 这个概念到底是什么，属于什么范畴 | 定义、所属领域、解决的核心问题 | 1（节点自身） |
| **L1** | 构成 | 它由哪几块组成，每块是什么 | 关键要素、子概念、组成部分 | 3–6 |
| **L2** | 机理 | 它内部怎么跑，因果链是什么 | 流程步骤、因果机制、公式、定理 | 3–6 |
| **L3** | 边界 | 什么条件下不成立 | 反例、失效条件、常见误解、禁忌 | 3–6 |
| **L4** | 关联 | 它和别的东西什么关系 | 前置知识、后继概念、近似概念、区别 | 3–6 |
| **L5** | 延伸 | 还能往哪走 | 进阶方向、变体、开放争议、应用场景 | 3–6 |

**层级的硬约束（Code Agent 必须实现）**
- 每个节点有且仅有 6 层，深度上限 = L5。L5 的子节点统一收纳到「延伸」桶，不再生成 L6。
- 节点总数软上限：**单树 500 节点 / 单节点子节点 6 个 / 每次 API 调用生成 1 层**（禁止一次生成多层，会导致幻觉和不可控）。
- 层是**相对当前节点**的，不是全局绝对深度。钻入后新树仍从 L0 开始（但保留路径面包屑）。

### 轴二：视角 Facet（环向扇区）—— 管"内容"

**每个节点内部有 7 个可切换的内容视角**，决定"这个节点展开后你看到什么"。用户可全局切换或单节点记忆。

| Facet | 中文名 | 内容 | 主要数据来源 | 默认开 |
|---|---|---|---|---|
| `overview` | 速览 | 三句话：是什么 / 为什么重要 / 一句话本质 | LLM | ✅ |
| `mechanism` | 原理 | 详细解释、步骤、公式、推导 | LLM | ✅ |
| `evidence` | 实证 | 具体案例、数据、实验、文献 | LLM + Web 检索（可选） | |
| `application` | 应用 | 使用场景、实操步骤、避坑 | LLM | |
| `controversy` | 争议 | 不同学派观点、局限、批评 | LLM | |
| `relation` | 关系 | 上游/下游/类比/对立/易混 | 图谱算法 + LLM | |
| `ask` | 追问 | 自由提问框（针对该节点） | 对话式 | |

> **为什么要双轴**：层解决"看得懂结构"，视角解决"读得深内容"。用户钻到 L3「机理」层时，切到「实证」视角立刻得到该层的案例，而不是被同一段散文重复 6 遍。**这也让同一份数据产生了 7 种阅读密度**，是留存的关键。

### 交互动作定义

| 动作 | 触发 | 结果 |
|---|---|---|
| **剥开（Expand）** | 单击节点的「+」/ 节点本体（未展开时） | 在该节点外侧生成下一层子节点（径向展开），带流式动画 |
| **钻入（Drill in）** | 双击节点 / 点击「以此为中心」 | 视图重心移至该节点，洋葱重新以它为核展开，路径面包屑 +1 |
| **切视角（Facet）** | 顶部扇区选择器 / 快捷键 `1–7` | 当前节点内容区切换视角，节点摘要文案同步刷新 |
| **追问（Ask）** | 节点内「追问」视角 | 对话式提问，答案落盘为该节点的新增「笔记卡」，可标记为「值得下钻」 |
| **标记掌握** | 快捷键 `M` / 详情页按钮 | 掌握度设为 已掌握 / 模糊 / 未懂，三态 |

## 3. 完整闭环设计

> 用户明确要求"整个产品必须要闭环"。以下闭环是本产品的**验收硬标准**，不是可选功能。

```
   ┌──────────────────────────────────────────────────────────────┐
   │                                                              │
   ▼                                                              │
[1] 播种 Seed ──→ [2] 剥层 Peel ──→ [3] 钻取 Drill ──→ [4] 检验 Quiz
   ▲                                                            │
   │                                                            ▼
[7] 再播种 ◀── [6] 重组 Remix ◀── [5] 复习 Review ◀───────────┘
```

| 阶段 | 做什么 | 出口（必须产出的数据） | 闭环回灌点 |
|---|---|---|---|
| **1 播种** | 输入一个知识点：文字 / 粘贴一段话 / 导入文件 / 从浏览器划词 / 语音口述 | 生成 L0 节点 + 知识树 | — |
| **2 剥层** | AI 按六层骨架逐层生成子节点 | 树结构 + 节点内容 | — |
| **3 钻取** | 用户点击下钻，任意节点成为新中心 | 浏览路径 = 路径面包屑 | 浏览路径喂给 L4 关联层（上下文相关，不相关不生成） |
| **4 检验** | 一键生成针对当前节点的 3–5 道题（选择/简答/判断），即时判分 | 掌握度评分 + 错题记录 | 错题指向的知识点**自动标记为待展开**，回到 [2] |
| **5 复习** | 间隔重复调度（SM-2），今日复习队列 | 复习记录 + 掌握度衰减 | 连续答错 2 次 → 该节点及其子树**自动重新排入待展开队列**，回到 [2] |
| **6 重组** | 跨节点串联：发现两个知识点的桥接节点、生成一张关联图 | 桥接节点 + 图谱边 | 新桥接节点作为一个新 L0 种子，回到 [1] |
| **7 再播种** | 用户带着新的认知回到起点 | 新知识树 | — |

**三条必须实现的闭环回灌链路（Code Agent 验收项）**
1. `Quiz 错题 → 该知识点标记 needsExpand → 洋葱图上该节点显示橙色「待补全」角标 → 用户点击即可被引导展开`
2. `连续复习失败 ≥2 次 → 节点状态置为 fragile → 其所在层重新开放生成（并提示"上次这里你答错了"）`
3. `知识缺口检测：扫描全树，找出 L1 缺失/只有一个子节点/长期未复习的分支 → 生成「待补全清单」→ 点击直达对应节点并展开`

### 3.5 探索模式：引导串（v1.1 新增）

> 本节来自对 rabbithole.chat 的逆向分析，详见 `06-竞品分析与方案修订-Rabbithole.md`

前面五节解决了"结构不跑偏"，但留了一个空缺：**用户面对空白画布，不知道第一步该点什么。**

Rabbithole 用「分支式引导问卷」解决了这个问题 —— AI 生成一串带跳转规则的问题，用户的回答决定接下来看到什么。我们吸收这个机制，但让产物**落进洋葱树**。

#### 3.5.1 引导串模型

```ts
interface GuidedStep {
  id: string;
  question: string;
  type: 'single_choice' | 'multiple_choice' | 'rating' | 'open';
  choices?: string[];
  scale?: 3 | 5 | 7 | 10;
  /** 用户所选答案原文（open 时为文本） */
  response?: string;
  branching?: {
    type: 'next_question' | 'response_based' | 'specific_question' | 'end';
    index?: number;                             // specific_question 用
    responseValues?: Record<string, number>;   // response_based 用：选项索引 → 目标步序号
  };
  /** 本步骤生成的洋葱节点 */
  nodeId?: string;
  answeredAt?: number;
}
```

**四种回答类型**：单选、多选、评分（3/5/7/10 量表，含 NPS 0-10 分档）、开放式文本。

**四种跳转规则**：

| 规则 | 行为 | 语义 |
|---|---|---|
| `next_question` | 索引 +1 | 顺次推进 |
| `response_based` | 按所选选项索引查 `responseValues` | **真正分叉的树** |
| `specific_question` | 直接跳到 `branching.index` | 回跳补问 |
| `end` | 终止探索 | 收尾 |

#### 3.5.2 与洋葱的关系

**引导串与洋葱树共享同一份数据** —— 这是关键设计，不是两套东西：

```
用户输入宽泛问题「工业革命」
   ↓
AI 生成引导串（5-9 步，带分支规则）
   ↓
用户逐题回答 ──→ 回答决定下一跳（response_based）
   ↓
每答一题，同时生成一个洋葱节点（含 essence + 七视角）
   ↓
引导串作为一棵子树挂在根节点下（L4 关联层）
   ↓
最终得到一棵带真实交互历史的知识树
```

用户在引导串中可随时「钻入洋葱」查看该节点的完整七视角；在洋葱里追问的答案也可固化回引导串。

#### 3.5.3 回答的双重作用（我们比 Rabbithole 多的一层）

| 用户行为 | 掌握度影响 | 缺口影响 |
|---|---|---|
| 选择某选项 | 该选项关联节点 `score += 8` | — |
| 选择"不了解/想跳过" | — | 对应节点 `needsExpand = true` |
| 评分题低分 | 当前节点 `score -= 15` | — |
| 开放回答（非空） | 当前节点 `score += 5`，答案存为笔记卡 | — |
| **走到 end** | — | **未走到的分支全部标记 `needsExpand`** |

最后一条是关键增量：**一次探索的"未走路径"天然就是一张待学清单。** Rabbithole 没有这个能力，因为它的路径是一次性的。

#### 3.5.4 与原闭环的关系

引导串是闭环的**入口加速器**，不是替代品：

```
[1] 播种 ──→ [1.5] 引导（可选）──→ [2] 剥层 ──→ [3] 钻取 ──→ [4] 检验
     ↑                                                   │
     └────── [7] 再播种 ← [6] 重组 ← [5] 复习 ←───────────┘
```

跳过引导串，直接在洋葱里点开节点展开，完全可行。引导串只是给新用户一条明确的起跑线。

#### 3.5.5 实现约束（硬要求）

| 约束 | 原因 |
|---|---|
| **逐步生成，不预生成整串** | 预生成首响应慢、token 贵。答完一题才生成下一题（滑动窗口，一次只多备 2 问） |
| **必须做环检测与索引越界校验** | 分支索引错乱会导致死循环，这是分支问卷最大的线上风险。校验失败降级为 `next_question` |
| **必须做可达性检查** | 走不到的步骤要补一条兜底边，否则用户会卡在死胡同 |
| **最后一步必须能终止** | 否则会话永远结束不了 |
| 引导串生成 Prompt 见 `01-AI引擎与多模型适配规范.md` §7 | |

## 6. 关键算法规范

### 6.1 展开算法（ExpandEngine）

```
输入: parentNode, layerIndex(0..5), facetContext(当前视角), pathContext(面包屑路径), siblingTitles
步骤:
  1. 校验 layerIndex ≤ 5，否则拒绝并提示"已到延伸层"
  2. 组装 prompt:
     - SYSTEM: 角色 + 六层语义定义 + 严格 JSON 输出约束
     - USER: 节点标题 + 一句话定义 + 当前层语义目标 + 已存在的兄弟节点标题(去重)
                + 路径上下文(仅当 layer == L4 关联层时注入)
  3. 调用 provider.chat({ messages, temperature: 0.6, json: true })
  4. 解析 JSON → { children: [{ title, essence, detail, relation }] }
  5. 校验: 数量 3..6；title 去重（与兄弟 + 祖先比较）；长度限制
  6. 失败重试: 最多 2 次，退避 1s/3s；仍失败则降级为"手动添加子节点"入口
输出: 新建子节点数组，parentId = parentNode.id，layer = layerIndex+1
```

**防幻觉与防重复约束（必须写进 prompt）**
- 明确要求"不得与以下已有概念重复：..."
- 要求每个子节点必须给出「一句话本质 essence」，长度 15–40 字
- 明确要求"若不确定宁可不生成，宁可少生成"
- 输出用 JSON，解析失败走容错提取（正则捞第一个 `[...]` 块）

### 6.2 掌握度模型

```
state: 'mastered' | 'fuzzy' | 'unknown'
score: 0..100  （连续分，用于排序与图谱着色）

初始：生成时 score = 40（刚生成，未验证）
答对 1 题：score += 12 (上限 100)
答错 1 题：score -= 18 (下限 0)
标记为 mastered：score = max(score, 92)，并写入 review
标记为 fuzzy：score = min(score, 55)
标记为 unknown：score = min(score, 25)，同时该节点 needsExpand = true

L1..L5 层的 score 由子树加权平均得出：
  节点有效 score = 0.7 * 自身 score + 0.3 * 子树平均 score
（用于洋葱图上同心环的整体着色，让"哪一圈最虚"一眼可见）
```

### 6.3 布局与高亮（v1.2 改用 React Flow + ELK）

> 原 §6.3 的自研径向布局降级为 P2 可选视图。v1.2 采用 Rabbithole 已验证的方案。

```ts
// ① 布局：ELK layered 算法，自动排位
import ELK from 'elkjs/lib/elk.bundled.js';

const elk = new ELK();
async function layoutTree(nodes: OnionNode[], edges: Edge[]): Promise<Layout> {
  const graph = {
    id: 'root',
    layoutOptions: {
      'elk.algorithm': 'layered',
      'elk.direction': 'RIGHT',       // 从左到右生长，像思考的流向
      'elk.spacing.nodeNode': '48',
      'elk.layered.spacing.nodeNodeBetweenLayers': '80',
    },
    children: nodes.map(n => ({ id: n.id, width: 600, height: 180 })),
    edges: edges.map(e => ({ id: e.id, sources: [e.fromId], targets: [e.toId] })),
  };
  return elk.layout(graph);
}

// ② 路径高亮：悬停节点 → 高亮其所有祖先边
export function getAncestorEdgeIds(
  nodeId: string,
  nodes: Map<string, { type: string; data: { node: OnionNode } }>,
  edges: Edge[],
): Set<string> {
  const ids = new Set<string>();
  let cur = nodeId;
  const node = nodes.get(cur);
  // 追问节点的起点是它引用的原节点
  if (node?.type === 'followUpNode') {
    const e = edges.find(x => x.target === cur);
    if (e) cur = e.source;
  }
  while (cur) {
    const e = edges.find(x => x.target === cur);
    if (!e) break;
    ids.add(e.id);
    cur = e.source;
  }
  return ids;
}

// ③ 边的两态样式（transition 是丝滑的关键）
export const EDGE_DEFAULT   = { stroke: '#374151', strokeWidth: 2, transition: 'stroke 0.2s ease' };
export const EDGE_HIGHLIGHT = { stroke: 'hsl(var(--brand))', strokeWidth: 2, transition: 'stroke 0.2s ease' };
```

#### 原自研径向布局（降级为 P2 可选视图）

保留规格见下（供 P2 使用）

```
输入: rootNode, tree, viewport {cx, cy, innerRadius=110, ringGap=150}
输出: 每个节点的 { x, y, r, angle, layer, sectorIndex }

1. 以当前中心节点为根，取其整棵子树
2. 计算树深度，取 maxDepth（≤5）
3. 环半径: ringRadius(layer) = innerRadius + layer * ringGap
4. 每个节点的子节点在其父节点所占角度区间内均分：
   - 根节点占据整圆 0..2π
   - 某节点角度区间 [a0, a1]，其 n 个子节点各占 (a1-a0)/n
   - 若某子节点本身还有子，则该子节点的区间 = 父区间内按子树叶子数加权分配
     （leaf-count proportional，保证不重叠）
5. 节点坐标: x = cx + r*cos(θ), y = cy + r*sin(θ)，θ = 区间中点
6. 扇区角宽 = 区间宽度，用于绘制底层色带（facet 色）
7. 缩放: 整体套一层 zoom transform，滚轮缩放 / 拖拽平移
```

**扇区着色规则**：每个节点根据其**父层语义（L1..L5）**取色 —— 因为层是固定的，环带颜色全局一致，用户能形成肌肉记忆：
L1 构成 = 靛蓝 / L2 机理 = 青 / L3 边界 = 琥珀 / L4 关联 = 紫 / L5 延伸 = 品红 / L0 核心 = 中性墨色

```
触发: 手动点击「检测缺口」 或 每次保存后后台低频跑
规则（命中任一即标记 needsExpand）:
  R1 节点只有 1 个子节点（内容偏薄）
```

## 10. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 厂商 CORS 限制导致浏览器无法直连 | 中 | 高 | ① 优先选 CORS 友好的厂商顺序；② 抽象层预留 `proxyUrl` 配置项（用户自建反代）；③ 后续 Tauri 壳内用原生 fetch 绕过 CORS |
| API Key 泄露 | 低 | 极高 | 默认不持久化（可选「记住」需用户显式勾选 + 二次确认）；AES-GCM 加密；设置页明示；日志绝不打印 key |
| LLM 幻觉污染知识树 | 高 | 中 | 每层生成带"宁缺毋滥"约束；子节点必须有 essence；提供「存疑」标记与溯源位；提供一键「重新生成」与「删除该分支」 |
| 展开成本失控（点一下几十块） | 中 | 中 | 每次调用只生成 1 层；调用前显示预估 token；响应缓存（prompt hash）；支持"仅本地模型展开"策略 |
| 结构太固定导致不灵活 | 中 | 中 | 六层为默认骨架，v1.2 开放「自定义层模板」；facet 已提供横向自由度 |
| 用户不会用 | 中 | 高 | 首屏零状态引导；命令面板；键盘流；3 步内产出第一棵树 |

## 11. 合规与内容安全

- 用户输入与 AI 输出均可能含敏感信息：默认不持久化任何第三方内容到自有服务
- 涉政/涉黄/医疗诊断等高风险问题：在 system prompt 中加通用拒答约束 + 前端展示免责提示
- 生成内容页脚常驻「AI 生成内容，仅供参考」+ 每节点可手动标注可信度
- 若后续加入分享功能，必须显式提示用户"分享的内容会包含你写的笔记"
